# Проекты в S3, публичные проекты, MCP пользователя: план реализации

> **For agentic workers:** порядок задан пользователем: тесты пишет субагент по спеке (Задача 1), реализацию ведёт основной агент (Задачи 2–10), затем циклы исправлений и ревью субагентом (Задача 11). Шаги отмечаются чекбоксами (`- [ ]`).

**Goal:** несколько именованных проектов пользователя в S3, публикация и копирование с `sealed`-файлами, MCP на пользователя через вкладки `/mcp-driven`.

**Architecture:** сервер выдаёт presigned URL и хранит `users`/`projects`, а данные идут напрямую браузер ↔ S3 в виде gzip-Yjs-состояний. Одна загрузка страницы показывает один проект; смена проекта — навигация. MCP-вызовы идут по отдельному WebSocket вкладки, реестр вкладок живёт в памяти одного экземпляра бэка.

**Tech Stack:** Go 1.26, Postgres, `github.com/minio/minio-go/v7` (клиент S3 для любого провайдера), MinIO в compose, React 19, Yjs, `CompressionStream`, vitest, puppeteer-core.

**Spec:** `docs/superpowers/specs/2026-11-02-projects-s3-design.md`

## Global Constraints

- Срок presigned URL 5 минут; досмотр удаления через 6 минут.
- До 100 операций в одном presign; 64 МБ на проект, 1 ГБ на пользователя.
- Автосохранение через 2 секунды после последней правки; смена видимости файла сохраняется сразу.
- Таймаут `open_project` 60 секунд; лимит MCP 600 вызовов в минуту на пользователя.
- Токен: 32 случайных байта, в БД только sha256.
- Чужой или приватный проект для постороннего всегда 404.
- UI-строки через `t()` на en и ru. Код в стиле окружения. После изменений `npx tsc -b`, `npx oxlint src`, `gofmt`, `go vet`.
- Контракты 62 существующих инструментов не меняются.

## Review Focus

1. Файл скрывают в публичном проекте, а сохранение не удалось: файл не должен молча оставаться в `public/`; статус «не сохранено» и повтор, пока объект не исчезнет. Тест в Задаче 5.
2. Файл или папку переименовали в папку роли либо назначили роль уже заполненной папке: объекты переезжают в `private/`, из `public/structure` имена исчезают. Тест в Задаче 5.
3. `sealed`-путь занимают не только `create_file`, а также `renamePath`, загрузка файла, импорт архива и MCP `write_file`: старый `sealed` заменяется, чтение не возвращает его текст. Тест в Задаче 6.
4. Перезагрузка против дубликата: перезагрузка сохраняет `tab_id` и проект, дубликат получает новый id и не вытесняет оригинал. Тест в Задаче 8.
5. Проект удалили, пока идёт сохранение или открыта другая вкладка: следующий presign получает 404, вкладка прекращает запись и не воскрешает проект из IndexedDB. Тест в Задаче 3 и Задаче 5.
